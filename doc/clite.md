# clite
clite: client lite

如果你的客户端本来就很简单，那么你应该守住这珍贵的简单，这是 clite 的唯一目的。
但如果你的前端交互比较复杂，clite 不能把它变简单，这时 clite 是不适用的。

> 以下提到的“分离模式”即前后端分离模式

##### 后端渲染 html

对后端应用而言，相比复杂的 json，html 更小（流量小），渲染更快（性能消耗低）。

对前端应用而言，在分离模式中，对于后端响应的 json，前端可能要检查数据类型、格式化（比如日期）、渲染到页面上。
运行效率低是一方面，额外的开发成本、系统复杂度才是最烦人的。

偶有的复杂 ui，可以交给 [hyperapp](https://github.com/jorgebucaran/hyperapp)。

##### 静态文件（css、js 等）

用原方案，即 vite 等工具编译，文件名带 hash；
缓存策略为 immutable；
流量、请求次数都会降低。

vite 输出时，附带一个 manifest.json 文件，记录文件的 hash。
以供后端渲染时引用。

每个 html 页面都关联这唯一的 js 和唯一的 css 文件。

> 注意前提，“如果你的客户端本来就很简单，……”，想必打包后的唯一的 js 和唯一的 css 文件不会很大。
